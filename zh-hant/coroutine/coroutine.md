# 協程

`Swoole` 的協程是一種輕量級的**用戶態線程**。可以把它理解爲在進程內部、由程序員自己創建和調度的**子任務**，而不是由操作系統管理的線程。

它的核心價值在於：**用同步代碼的寫法，獲得異步非阻塞的性能**，尤其適合高併發的 `I/O` 密集型應用。

協程滲透在 `Swoole` 生命週期的方方面面，提前喫透這個概念，會爲後續學習所有核心知識打下最堅實的基礎。

## 舉個例子

想像這樣一個場景：需要完成兩個耗時均爲 **30 分鐘** 的任務——**洗衣服**和**做飯**。

### 傳統模式（同步 / 阻塞）

就像你守在洗衣機旁，必須等衣服洗完，然後纔開始做飯。

- **過程**：等待洗衣服（30m）➔ 做飯（30m）
- **結果**：總共用時 **60 分鐘**
- **缺點**：一個任務完成之後才能做下一個，等待期間 `CPU` 完全閒置——對應到程序中，就是進程阻塞在 `I/O` 上，什麼也沒做

### Swoole 協程模式

同樣兩件事，換一種執行順序就能實現「時間摺疊」：

1. **啓動洗衣機**：發起 `I/O` 請求。
2. **立刻「掛起」** 洗衣服這個任務，切換到做飯任務：這就是**協程切換**。
3. 做完飯後，衣服正好也洗好了，再**「恢復」** 洗衣服的任務，去晾曬。

**結果**：總共耗時僅 **30 分鐘**，效率直接翻倍。
